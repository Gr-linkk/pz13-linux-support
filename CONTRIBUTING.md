# Contributing

Contributions should help another owner reproduce a result or improve support upstream. Keep each change focused and give credit to the work it builds on.

For a hardware report, include the model and software versions, exact test steps, observed behavior, and whether the check was simulated, a build test or physical hardware. Share reviewed excerpts rather than full diagnostics. Keep serials, addresses, boot identifiers, credentials and personal media private.

For source changes, run the relevant local tests and the receiving project's required checks. Explain any remaining fault or untested boundary. Check existing issues and patches before proposing another implementation.

Update the hardware matrix only when the corresponding evidence exists. Adding a device name or producing a successful build is not a physical acceptance result.

Review private inputs, licensing and exported files before publication. New vendor data requires its own provenance and redistribution review. Use the file-level license appropriate to the component and preserve existing notices. AI-assisted changes require the same technical review and validation as other changes.
